# TIME LAB — лаборатория английских времён

Обучающая веб-игра для изучения 12 английских времён: формулы, конструктор предложений, поиск ошибок, диалоги, неправильные глаголы с озвучкой, интервальное повторение и персональный учебный план. Интерфейс на русском, задания на английском.

Игра — статическое SPA без сборщика и npm-зависимостей: HTML + CSS + обычный JavaScript. Аккаунты и облачное сохранение работают через **Supabase** (Auth + PostgreSQL с Row Level Security). Без настроек Supabase игра полностью работает в гостевом режиме: прогресс хранится в браузере.

> GitHub Pages только раздаёт файлы сайта. Регистрацией, паролями и базой данных занимается Supabase — это отдельный сервис, который нужно подключить (бесплатного тарифа достаточно).

---

## Возможности

- **12 лабораторий времён** с картой кампании, 8 этапами в каждой и финальным испытанием. Следующее время открывается только кнопкой «Открыть следующее время». Любую лабораторию можно открыть вручную — освоенной она от этого не считается.
- **Механики:** выбор формы, верно/неверно, несколько ответов, конструктор предложений с перетаскиванием, поиск ошибки, ввод формы, перевод со свободным вводом, диалоги с персонажами, «спасение временной линии», блиц на 60 секунд.
- **Адаптивность:** статистика по каждому грамматическому правилу. После 3 ошибок в правиле — короткий разбор, лёгкое задание, задание в новой ситуации и возврат к правилу позже. Повторение через 1 · 3 · 7 · 14 · 30 дней.
- **Профили:** регистрация по email и паролю, вход, выход, восстановление пароля, вход через Google (если включить), имя и аватар, удаление аккаунта со всеми данными, гостевой режим. Гостевой прогресс можно перенести в новый аккаунт.
- **Облачное сохранение:** после каждого задания прогресс сохраняется локально и отправляется в облако. Статус в шапке: «Сохранено», «Синхронизация…», «Не удалось сохранить», «Нет сети». Без сети всё копится локально и отправляется после восстановления связи.
- **Onboarding из 5 коротких экранов:** знакомство, опыт, способ начала (свой уровень A1–B2, диагностика на 15 вопросов или «с первого времени»), цель, ритм занятий. Каждый экран можно пропустить.
- **Персональный план:** маршрут на главной, рекомендуемая длительность, повторение прошлых тем, пропуск знакомых тем, дополнительная тренировка правил с систематическими ошибками. План меняется в настройках без потери истории.
- **Личный кабинет:** вкладки «Обзор», «Мои времена», «История», «Достижения», «Настройки». Вся статистика считается по реальным ответам.
- **Словарь неправильных глаголов:** 211 глаголов по алфавиту A–Z с вариантами форм (got/gotten, learned/learnt…), переводом, транскрипцией, примером и пометками BrE/AmE. Есть:
  - мгновенный поиск по V1, V2, V3 и по-русски;
  - алфавитная навигация и сортировка по частоте;
  - избранное и отметка «выучено»;
  - тренировка выбранных глаголов;
  - необязательный фильтр по типу форм.
- **Озвучивание (Web Speech API):** кнопки динамика у форм глаголов, примеров, реплик диалогов и правильных ответов. Настройки:
  - автоозвучка (по умолчанию выключена);
  - выбор голоса;
  - British или American English;
  - скорость 0.75x / 1x / 1.25x;
  - «Повторить последнее».

  Если браузер не поддерживает синтез речи, игра работает без звука и показывает понятное сообщение.
- **Данные:** экспорт прогресса в JSON-файл, импорт, сброс прогресса, удаление аккаунта.

## Быстрый старт (локально, гостевой режим)

Нужен только Python 3 (есть в macOS и большинстве Linux).

```bash
bash scripts/dev.sh
```

Откроется сервер на http://localhost:8080/. Без `.env` игра работает в гостевом режиме.

Другой порт: `bash scripts/dev.sh 3000`.

## Подключение Supabase (аккаунты и облако)

### 1. Создай проект

1. Зарегистрируйся на https://supabase.com и создай проект (регион — ближайший к пользователям).
2. **Project Settings → API**: скопируй **Project URL** и публичный ключ **anon** (или **publishable**, начинается с `sb_publishable_`).
   - Ключ `service_role` / `sb_secret_...` **никогда** не вставляй в проект — сборка откажется его публиковать.

### 2. Создай таблицы

**SQL Editor → New query** → вставь целиком файл `supabase/migrations/20261031000000_timelab_init.sql` → **Run**.

Миграция создаёт таблицы `profiles`, `user_settings`, `learning_plans`, `tense_progress`, `skill_progress`, `exercise_attempts`, `achievements`, `irregular_verb_progress`, `review_schedule` и `study_sessions`. Ещё она:
- включает Row Level Security с политиками «только свои строки»;
- создаёт профиль при регистрации;
- создаёт функцию `delete_my_account()` для удаления аккаунта.

Миграцию можно запускать повторно: она ничего не удаляет. Если установлен Supabase CLI, то же самое делает `supabase db push`.

### 3. Настрой авторизацию

**Authentication → URL Configuration**:
- **Site URL**: адрес сайта, например `https://<логин>.github.io/<репозиторий>/`.
- **Redirect URLs**: добавь `https://<логин>.github.io/<репозиторий>/**` и для локальной разработки `http://localhost:8080/**`.

Без этого ссылки из писем (подтверждение email, сброс пароля) не вернут пользователя в игру.

**Authentication → Providers → Email**: оставь включённым. «Confirm email» можно оставить — игра покажет «проверь почту». Стандартный почтовый сервис Supabase сильно ограничен по количеству писем. Для реальных пользователей подключи свой SMTP: **Authentication → Emails → SMTP Settings**.

### 4. Вход через Google (необязательно)

1. В Google Cloud Console создай OAuth Client ID (тип Web application).
2. В **Authorized redirect URIs** укажи `https://<project-ref>.supabase.co/auth/v1/callback`.
3. В Supabase: **Authentication → Providers → Google** → включи и вставь Client ID и Client Secret. Секрет хранится только в Supabase, не в коде игры.
4. В настройках сборки поставь `GOOGLE_AUTH=true`. Пока это не сделано, кнопка Google не показывается.

### 5. Локально с облаком

```bash
cp .env.example .env
```

Впиши в `.env` значения `SUPABASE_URL` и `SUPABASE_ANON_KEY`, затем запусти:

```bash
bash scripts/dev.sh
```

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `SUPABASE_URL` | для облака | `https://<project-ref>.supabase.co` |
| `SUPABASE_ANON_KEY` | для облака | публичный anon/publishable-ключ. Его можно показывать в браузере: доступ ограничен RLS |
| `GOOGLE_AUTH` | нет | `true`, чтобы показать вход через Google |
| `SITE_URL` | нет | адрес сайта для писем. По умолчанию — текущий адрес страницы |
| `BASE_PATH` | нет | base path сайта (`/repo/`). В GitHub Actions вычисляется автоматически |

## Сборка

```bash
bash scripts/build.sh
```

Результат появится в `dist/`. Сборка:
- проверяет настройки;
- отклоняет секретные ключи;
- создаёт `js/config.js` и `404.html` с нужным base path;
- добавляет к скриптам версию (`?v=хеш`), чтобы после обновления не грузился старый код из кеша;
- если установлен Node.js, проверяет синтаксис JS.

## Публикация на GitHub Pages

1. Создай **публичный** репозиторий на GitHub, например `timelab`. README, .gitignore и лицензию при создании не добавляй.
2. Отправь в него этот проект (команды по одной):

   ```bash
   git init
   ```

   ```bash
   git add .
   ```

   ```bash
   git commit -m "TIME LAB"
   ```

   ```bash
   git branch -M main
   ```

   ```bash
   git remote add origin https://github.com/<логин>/timelab.git
   ```

   ```bash
   git push -u origin main
   ```

3. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. **Settings → Secrets and variables → Actions → Variables → New repository variable** — добавь:
   - `SUPABASE_URL`;
   - `SUPABASE_ANON_KEY`;
   - по желанию `GOOGLE_AUTH` (`true`) и `SITE_URL`.

   Это переменные, а не секреты: anon-ключ публичный по своей природе. Если их не задать, сайт соберётся в гостевом режиме.
5. **Actions → Deploy to GitHub Pages → Run workflow**. Workflow также запускается при каждом push в `main`.
6. Публичная ссылка появится в **Settings → Pages** и в логе шага deploy: `https://<логин>.github.io/timelab/`. Добавь этот адрес в Supabase (шаг 3 раздела «Подключение Supabase»).

Маршруты — hash-ссылки (`…/timelab/#/verbs/lib`), поэтому страница открывается после обновления на любом экране. Если кто-то откроет путь без `#` (например, `…/timelab/verbs/lib`), `404.html` перенаправит на нужный экран.

## Как устроены данные и безопасность

- **Пароли** проверяет и хранит только Supabase Auth (в виде хеша). Игра не сохраняет пароли ни в localStorage, ни где-либо ещё. В браузере хранится только токен сессии Supabase.
- **Row Level Security** включена на всех таблицах. Политики проверяют `user_id = auth.uid()` при чтении, записи, изменении и удалении. Подмена `user_id` в запросе не даст ни прочитать, ни записать чужие строки. Анонимной роли доступ к таблицам закрыт.
- **Разделение данных на устройстве.** У гостя и у каждого вошедшего пользователя — свой ключ localStorage (`timelab.v1` и `timelab.u.<id>`). При выходе локальная копия профиля удаляется. Если есть неотправленные изменения, игра предупредит.
- **Синхронизация** построчная. Неизменённые строки не отправляются. Журнал ответов и история занятий только дополняются.
- **Конфликты** (прогресс на двух устройствах, одно было офлайн) решаются так:
  - XP и счётчики складываются по приросту с последней синхронизации;
  - этапы, значки и достижения объединяются;
  - по правилу или глаголу остаётся более полный результат;
  - настройки и план берутся по времени изменения.

  Более новый прогресс не удаляется молча.
- **Перенос гостевого прогресса.** При первом входе игра спрашивает, переносить ли его. Если в аккаунте уже есть прогресс, данные объединяются.
- **Удаление аккаунта:** «Профиль → Настройки → Удалить аккаунт». Функция `delete_my_account()` удаляет пользователя, и все его строки каскадно удаляются из всех таблиц. Экспорт в JSON — там же.
- **Старый прогресс** первой версии (ключ `timelab.v1`) подхватывается автоматически: сохранение обновляется до версии 2 без потери данных.

## Что настроить вручную

1. Создать проект Supabase и выполнить SQL-миграцию.
2. Указать Site URL и Redirect URLs в Supabase Auth.
3. (Рекомендуется) Подключить свой SMTP для писем.
4. (По желанию) Включить Google-провайдер и `GOOGLE_AUTH=true`.
5. Создать репозиторий GitHub, включить Pages → GitHub Actions, добавить переменные `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
6. После первого деплоя пройти сценарии из таблицы на реальном Supabase. Особенно важно: вход с двух устройств и попытка прочитать чужие данные.

## Дальнейшее развитие

- Озвучивание вынесено в `js/speech.js`. Через `Speech.use({ id, supported, speak(text) })` можно подключить записанные аудиофайлы или внешний TTS-сервис без изменений в остальном коде.
- Режим тренировки произношения через микрофон (Web Speech Recognition) пока не реализован. Под него есть место в том же сервисе.
